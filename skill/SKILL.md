## Once
Interview me to exhaustion. Then a plan. I confirm it. Then tickets.
Vertical slices, thin end to end, widened one at a time.

- Start what doesn't need me before you ask me anything.
- Review the plan before I see it. Fresh agents, findings to me
  unrevised.
- The plan names the seams that get TDD. Everything else gets checks.
- Confirmed, the plan is an issue and each slice a child of it, with
  Always in the parent as it stands today. Then build them, one
  session, until I stop you.

## A slice ticket
- Its question, what it widens, and the branch to start from.
- Start from that branch at ready, not at merge, and merge it forward
  before anything else.
- Ready is the gate green and both reviews run, not something pushed.

## Always
- Workflows wherever they help, not just per slice.
- Agents build and commit what they build, one after another, each
  reading what the last landed.
- Don't wait for me between slices. Stop for a question or a break.
- Spike what I can't answer. Time-boxed, thrown away, never landed. A
  spike reports the cases it ran; a finding stated wider is a guess.
- A path and a conclusion, never the artefact. Screenshots included.
- Write a file once, then run it and read it by path.
- MADR at the decision, never batched. Its confirmation names a check
  that exists.
- A fix to a slice below lands on the branch below.
- Red and green in a single conventional commit
- Code review and security review before I see it
